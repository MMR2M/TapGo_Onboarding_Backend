# TapGo Onboarding App

This project now includes a real backend, not just a front-end prototype.

## What it does

- Provides the TapGo onboarding API
- Validates business and contract data server-side
- Stores submissions in SQLite
- Stores uploaded menu files on disk
- Accepts menu uploads or a shared menu link
- Generates a contract PDF bundle from the submitted data
- Saves digital signatures
- Creates internal and customer emails
- Uses SMTP when configured, or writes `.eml` files to a local outbox in development
- Supports optional IMAP credential checks for mailbox access validation
- Creates a Stripe Checkout session when a Stripe secret key is configured
- Syncs Stripe payment status back into the database via return flow and webhook
- Uploads generated artifacts to S3-compatible object storage when configured
- Falls back to development payment mode when Stripe is not configured

## Project structure

- `app.py`: Flask backend
- `templates/contract_bundle.html`: server-rendered contract PDF template
- `data/`: runtime database, generated contracts, uploaded files, and outbox emails

## Run locally

1. Create a virtual environment if you want an isolated setup:

```bash
python3 -m venv .venv
source .venv/bin/activate
```

2. Install dependencies:

```bash
pip install -r requirements.txt
```

3. Optional: copy environment settings:

```bash
cp .env.example .env
```

4. Start the app:

```bash
python3 app.py
```

5. Open:

```text
http://localhost:8000
```

## Production deployment (Ubuntu + Nginx + Gunicorn)

1. Prepare server:

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip nginx
```

2. Place the backend at `/opt/tapgo-backend` and the UI repository at
   `/opt/tapgo-ui`, then install backend dependencies:

```bash
cd /opt/tapgo-backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

3. Configure `.env` (production values):
- `TAPGO_BASE_URL=https://contract.tapgo.ch`
- `TAPGO_ENV=production`
- `TAPGO_HEALTH_TOKEN=<long random value>`
- `TAPGO_STRIPE_SECRET_KEY=sk_live_...`
- `TAPGO_STRIPE_WEBHOOK_SECRET=whsec_...`
- SMTP and object storage vars

Start from `deploy/.env.production.example`. Enter secrets directly on the
server and restrict the file to the service account:

```bash
sudo install -o www-data -g www-data -m 600 deploy/.env.production.example /opt/tapgo-backend/.env
sudo nano /opt/tapgo-backend/.env
```

4. Install systemd service:

```bash
sudo cp deploy/tapgo.service /etc/systemd/system/tapgo.service
sudo systemctl daemon-reload
sudo systemctl enable tapgo
sudo systemctl start tapgo
sudo systemctl status tapgo
```

5. Install Nginx site:

```bash
sudo cp deploy/nginx.contract.tapgo.ch.conf /etc/nginx/sites-available/contract.tapgo.ch
sudo ln -s /etc/nginx/sites-available/contract.tapgo.ch /etc/nginx/sites-enabled/contract.tapgo.ch
sudo nginx -t
sudo systemctl reload nginx
```

6. Enable SSL (Let's Encrypt):

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d contract.tapgo.ch
```

## Development behavior

- If SMTP is not configured, emails are written to `data/storage/outbox/`
- If Stripe is not configured, the app marks the one-time payment as simulated
- If object storage is configured, generated contracts, signatures, summaries, and menu files are uploaded there too
- If `TAPGO_PDF_ENGINE=chrome`, the app uses headless Chrome to generate real PDFs
- If `TAPGO_PDF_ENGINE=libreoffice`, the app tries LibreOffice instead
- If `TAPGO_PDF_ENGINE=stub`, the app creates a lightweight placeholder file for testing

## API endpoints

- `GET /health`
- `GET /api/config`
- `GET /api/integrations/health`
- `POST /api/contracts/preview`
- `POST /api/submissions`
- `GET /api/submissions/<reference>`
- `GET /api/submissions/<reference>/contract`
- `POST /api/submissions/<reference>/retry-payment`
- `POST /api/submissions/<reference>/payment-sync`
- `POST /api/stripe/webhook`

## Notes

- In production, call `/api/integrations/health` with
  `Authorization: Bearer <TAPGO_HEALTH_TOKEN>`.
- Customer submission details, payment actions, and contract downloads use
  per-submission access tokens generated by the server.
- The app stores data locally by default, which is good for development but not enough for production hosting.
- For production, configure real SMTP, Stripe, and object storage credentials in `.env`.
- For Stripe webhook sync, set `TAPGO_STRIPE_WEBHOOK_SECRET` and point Stripe webhook events to `/api/stripe/webhook`.
- SQLite is tuned with WAL mode and busy-timeout for better concurrency. For heavier sustained traffic, migrate to PostgreSQL.
